**SchemaRenderer component (frontend/components/SchemaRenderer.tsx):**

Create a "use client" component that renders JSON Schema objects in a human-readable format. This is a custom component -- do NOT use react-json-tree or any external dependency.

Props: `{ schema: Record<string, unknown> }`

Rendering logic:
1. If `schema.type === 'object'` and `schema.properties` exists:
   - Render each property as a row showing:
     a. Property name in monospace font (--font-mono, --color-accent for the name)
     b. Type badge using .badge.badge-neutral (e.g., "string", "number", "boolean", "array", "object")
     c. "required" badge in .badge.badge-error if the property name is in schema.required array
     d. Description text in --color-text-secondary if present
     e. Enum values: if property has `enum`, show "Allowed: value1, value2, ..." in --color-text-muted
     f. Default value: if property has `default`, show "Default: {value}" in --color-text-muted
     g. For nested objects (property.type === 'object' and property.properties exists): recursively render SchemaRenderer with indentation (padding-left)
     h. For arrays (property.type === 'array' and property.items exists): show "Items:" label then render items schema
   - Each property row gets a light background (--color-bg-secondary), rounded corners (--radius-md), and padding (--space-3)
   - Space between rows with gap-2

2. If schema does not match the object pattern (missing properties, unknown type, or malformed):
   - Fallback: render the raw JSON in a `<pre>` block with --color-bg-tertiary background, monospace font, and overflow-x-auto
   - This handles edge cases per 03-RESEARCH.md pitfall 4

3. Add null/undefined guards throughout: if schema is nullish, render a "No schema available" message in --color-text-muted.

**MCP Tool Browser Page (frontend/app/integrations/mcp/[id]/tools/page.tsx):**

Create a "use client" page that displays all tools for an MCP server.

Implementation:
1. Use `useParams()` to get the server `id`
2. Fetch server data via `mcpServersAPI.get(id)` on mount
3. Extract `server.tools_detected` (which is `Array<Record<string, unknown>>`)
4. Track `expandedTools` as a `Set<string>` state for which tools have their schema visible

Page layout:
1. Wrap in DashboardLayout
2. Header section:
   - "Back to MCP Servers" link (to /integrations/mcp) using .btn.btn-ghost.btn-sm
   - Title: "{server.name} -- Tools" using .header-title
   - Subtitle: "{N} tools discovered" in .text-secondary
   - Server status badge next to title

3. Tool list:
   - If tools_detected is empty: show empty state with the existing .empty-state classes, message "No tools detected. Try syncing the server to discover tools.", and a "Sync Now" button that calls `mcpServersAPI.sync(id)` then refetches

   - For each tool in tools_detected:
     a. Render a .card with:
        - Tool name in `<code>` with --color-accent color and monospace font
        - Tool title (if present) as secondary text next to name
        - Tool description (if present) below name in --color-text-secondary
        - "Expand Schema" / "Collapse" toggle button (.btn.btn-ghost.btn-sm) on the right side
     b. When expanded and tool.inputSchema exists:
        - Show a "Input Schema" section header
        - Render `<SchemaRenderer schema={tool.inputSchema} />`
        - If tool.inputSchema is missing, show "No input schema defined" in muted text
     c. When expanded and tool.outputSchema exists (optional per MCP spec):
        - Show "Output Schema" section with SchemaRenderer

4. Loading state: show "Loading tools..." with DashboardLayout wrapper
5. Error state: show error message with retry button
6. Type the tools loosely (Record<string, unknown>) and access properties defensively with optional chaining since tools_detected comes from the MCP server and may vary in shape.
